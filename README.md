## 1. EOA(Externally Owned Account) 지갑
EOA는 이더리움과 같은 EVM기반 블록체인에서 가장 기본이 되는 계정 형태. 우리가 흔히 사용하는 메타마스크, Ledger 등이 모두 EOA 방식.

핵심 구조는 privateKey & publicKey 와 publicKey를 해시하여 만든 주소(address) 로 이루어진다. 

이더리움에서 모든 변화는 EOA로부터 시작되어 잔액(balance)와 해당계정에서 보낸 트랜잭션의 횟수(nonce) 만 저장한다. 사용자가 트랜잭션을 만들고 개인 키로 서명하면, 네트워크 노드들은 이 주소의 개인 키 소유자가 승인한 것이 맞다는 것을 검증하고 실행한다.

### 1-1. EOA의 장점

* 낮은 비용 : 트랜잭션 실행시 추가적인 코드 실행이 없어 가스비가 가장 저렴하다.
* 범용성 : 모든 거래소, DApp, 지갑 서비스가 기본적으로 제공하는 표준.
* 단순함 : 인터넷 연결 없이도 종이에 개인 키를 적어두는것 만으로 자산을 보관하는것이 가능.

### 1-2. EOA의 한계

* 복구 불가능 : 개인키나 시드 구문을 잃어버리면 자산을 찾을 수 있는 방법이 아예 없음.
* 가스비 제약 : 전송하려는 토큰이 아무리 많아도, 가스비로 쓸 네이티브 코인이 없으면 지갑은 먹통이 됨.
* 유연성 부족 : "하루이체 한도 설정", "다중 승인" 같은 복잡한 규칙을 지갑에 설정하는 것이 불가능.


## 2. ERC-4337 기반 지갑

ERC-4337은 이더리움 생테계에서 계정 추상화 (Acount Abstraction) 을 구현하기 위해 제안된 표준이다. 
이 표준의 핵심은 "지갑을 단순한 열쇠(EOA)가 아니라 스마트 컨트랙트로 바꾸자" 는 것.
가장 중요한 특징은 이더리움 체인의 프로토콜을 바꾸지 않고도 구현할 수 있도록 설계되었다. 

### 2-1. 5가지 핵심 구성요소

1. UserOperation
기존의 트랜잭션 대신 사용하는 객체. '누가, 어디로, 무엇을 보낸다' 라는 정보와 함께 '어떤 지갑(컨트랙트)를 쓸 것인가' 에 대한 정보가 담김.


2. Bundler
여러 UserOperation을 모아 하나의 거대한 트랜잭션으로 묶는 역할을 함.
번들러는 이 묶음을 블록체인에 전달하고, 그 대가로 가스비 수익을 얻음.

3. EntryPoint
이더리움 네트워크에 딱 하나 존재하는 핵심 스마트 컨트랙트.
번들러가 보낸 묶음을 받아서 각 지갑의 주인임을 검증하고 실행하는 중앙 통제소 역할을 함.

4. Smart Contraction Wallet
사용자의 실제 계정. EntryPoint로 부터 명령을 받아 실제로 자금을 이체하거나 컨트랙트와 상호작용 함.

5. Paymaster
사용자가 가스비가 없을 때, 대신 내주거나 USDC같은 토큰으로 가스비를 받을 수 있게 해주는 중계 컨트랙트.
덕분에 사용자는 ETH가 없이도 서비스를 이용할 수 있다.

### 2-2. 작동 프로세스

기존 방식은 사용자가 직접 메인넷에 전송하지만, ERC-4337은 아래 단계를 거침.

1. 의사표시 : 사용자가 지갑 앱에서 '10USDC 전송' 버튼을 누르면 UserOperation이 생성
2. 대기실 (Alt Mempool) : 이 요청은 일반 트랜잭션 대기실이 아닌 별도의 대기실로 간다.
3. 묶음 및 배송 : 번들러가 이 대기실에서 여러 요청을 모아서 하나의 트랜잭션으로 만든 뒤 EntryPoint 컨트랙트로 던짐.
4. 검증 및 실행 : EntryPoint는 각 지갑 컨트랙트에 거래를 검증하고 검증이 완료되면 돈을 보낸다(실행).


### 2-3. ERC-4337의 장점

코인 지갑 쓰는 방식이 획기적으로 변함
* 시드 구문의 종말
  - 12 개의 단어를 종이에 보관할 필요 없이 OTP, 지문인식 등으로 지갑을 제어할 수 있고, 잃어버려도 가디언 등의 설정을 통해 복구 가능.
* 가스비의 유연성
  - 지갑에 ETH가 없어도 앱 서비스 운영자가 대신 내주거나, 내가 가진 USDC같은 다른 토큰으로 가스비 자동 결제 가능.
* 트랜잭션 묶기
    - DEX에서 코인을 교환할때에는 승인&교환 두번 서명이 필요하나, 이걸 한번의 클릭으로 묶어서 처리가 가능.
* 세션 키
  - 예를 들어, 블록체인 게임을 할 때, 아이템을 하나 주울때마다 서명을 해야된다고 하면, ERC-4337은 '앞으로 한시간동안 0.1ETH 미만의 거래는 승인없이 자동결재해줘' 같은 기간한정 권한 부여가 가능.


### 2-4. ERC-4337의 한계
* 비싼 가스비
  - 일반 EOA 지갑은 단순 서명만 확인하지만, ERC-4337은 스마트 컨트랙트 코드를 실행시키므로 가스비가 2~3배 비쌈
  - 이 때문에 가스비가 저렴한 L2 체인에서 주로 활용됨.
* 기술적 복잡성
  - 지갑 자체가 프로그램이기 때문에 버그가 있으면 해킹당할 위험성이 있음.


## 3. ERC-4337과 기존의 금융시스템
전통적인 금융 시스템과 ERC-4337(계정 추상화) 방식을 비교하여 블록체인이 어떻게 일반 은행 앱처럼 간편하면서도 고유의 강점을 유지하는지 알아보자.

* 신원 인증 및 로그인
  - 기존 금융은 실명확인, 신분증, 휴대폰 본인확인을 통해 은행이 내 신원을 보증함.
  - ERC-4337은 은행같은 중앙기관은 없지만, 스마트 컨트랙트 코드가 내 생체인증이나 이메일 인증을 검증함. => 중앙서버 없이도 은행앱처럼 로그인하는 것이 가능.

* 계정 복구
  - 기존 금융 : 고객센터 전화, 지점방문 등으로 은행이 제어권을 초기화해줄 권한을 가짐.
  - ERC-4337 : 사회적 복구 -> 가디언(나만이 지정한 신뢰 그룹) 들이 승인해주면 계정 주권을 되찾음

* 수수료
  - 기존 금융 : 송금 수수료를 통화로 차감하거나 혜택으로 면제 (시스템 유지비 명목)
  - ERC-4337 :원래 가스비(ETH) 가 필수지만, Paymaster 기술로 가스비 대납이 가능.

* 거래 제한 및 자동화
  - 기존 금융 : 1일 이체한도, 예약이체, 자동이체 등 은행이 정해둔 틀안에서 가능
  - ERC-4337 : 프로그래밍 가능한 한도나 특정 조건에 따라 자동화 기능을 직접 코드로 심을 수 있다.

* 자산의 통제권
  - 기존 금융 : 은행이 파산하거나 계좌를 동결하면 내 돈을 쓸 수 없음 (Custodial)
  - ERC-4337 : 지갑 서비스 업체가 망해도 내 자산은 블록체인 컨트랙트에 그대로 있음. 코드에 정의된 규칙만 맞으면 언제든 꺼낼 수 있음. (Non-custodial)


## 4. 블록체인의 트릴레마

블록체인 네트워크가 가진 세가지 핵심목표를 동시에 모두 완벽하게 달성하기는 매우 어렵다는 난제를 "블록체인의 트릴레마" 라고 한다.

### 4-1. 3대 요소
* 탈중앙화 
  - 중앙 서버 없이 전세계의 노드가 네트워크를 나누어 관리하는 정도
  - 검열저항성과 투명성을 보장한다.

* 보안성
  - 외부의 해킹 공격이나 데이터 변조로부터 네트워크를 얼마나 잘 보호하는지.
  - 자산의 안전을 보장.

* 확장성
  - TPS 같은 지표를 의미
  - 대중화를 위해 필수적, VISA 카드처럼 초당 수만건을 처리해야 실생활에서 사용이 가능.

### 4-2. 충돌의 예
* 탈중앙화 + 보안성 => 확장성 부족 
  - 비트코인, 이더리움 등 모든 거래를 일일이 검증하지만 속도가 매우 느림
* 보안성 + 확장성 => 탈중앙화 부족
  - 속도를 높이기 위해 노드 숫자를 줄이거나 검증 권한을 소수에게 집중시킴. 속도는 빠르지만 특정 집단이 네트워크를 통제할 위험이 존재.
* 탈중앙화 + 확장성 => 보안성 취약
  - 가장 위험하며 선택되지 않음. 노드가 많고 속도가 빠르려면 각 노드가 대충 검증해야되는데 이는 너무 취약함

### 4-3. 레이어 2 (Layer 2)
- 모든 거래 기록을 메인 체인에 올리지 않고, 다른 체인에서 거래를 발생시키고 이를 한꺼번에 묶어서 메인체인에는 결과만 기록하는 방식
- 메인넷의 보안과 탈중앙화는 빌려쓰면서, 확장성을 획기적으로 높이는 방식
- ERC-4337 과 L2과 결합했을 때, 가스비가 저렴해지고 속도가 빨라지면, ERC-4337의 복잡한 스마트 지갑 기능을 훨씬 저렴한 비용으로 마음껏 사용할 수 있게됨.

트릴레마는 인프라(메인넷) 의 문제이고, ERC-4337은 자동차(지갑) 의 편리함에 관한 문제이다.
도로는 넓어지고(L2), 자동차는 똑똑해지는 방향(ERC-4337)으로 블록체인이 발전하고 있다고 볼 수 있다.


## 5. 블록체인 도입시의 은행의 역할

### 5-1. 계정 복구용 가디언 은행
- 은행이 고객에게 ERC-4337 스마트 지갑을 발급
- 고객이 지갑의 개인 키를 잃어버렸을 때, 은행이 본인인증 후 지갑 권한 복구
- 고객 입장에서는 본인의 자산을 직접 소유(web3) 하면서도, 잃어버릴 걱정은 없는 신뢰를 제공하는게 가능.

### 5-2. Paymaster 도입
- 수수료 면제 혜택 제공 : 은행이 paymaster를 통해 가스비를 대신 내줌
- 원화 기반 수수료: 고객이 가스비로 지불할 코인이 없어도 지갑에 든 KRW 로 수수료가 결제되게 구현 가능
- 고객에게 높은 추상화 레벨의 서비스를 제공하여 블록체인을 쓰는지 모르지만 사용하고 있게끔 하는게 가능

### 5-3. 은행권 전용 L2 네트워크
- 기존 은행간의 결제가 금융결제원을 통해 이뤄지듯, 금융권 전용의 L2네트워크를 신설.
- 자금세탁방지 등을 스마트 컨트랙트에 로직을 넣어 규제 준수를 자동화하는것이 가능
- 블록체인의 투명성을 챙기고, 빠른 속도를 보장함과 금융 사고 위험을 차단하는 효과.

### 5-4. 실물자산의 토큰화
- 은행 예금을 토큰화하여 24/365 실시간 송금 및 결제가 가능하게끔
- 스마트 컨트랙트를 통해 토큰화된 부동산 등의 담보물의 가치가 떨어지면 자동으로 대출을 회수, 특정 조건 만족 시 이자 지급 등의 자동 금융상품 만드는게 가능
- 이로서 중간 관리비용을 줄이고 금융 상품의 회전율을 높일 수 있다.

### 5-5. 은행이 얻을 수 있는 이점
- 운영 비용 절감 : 정산, 대조, 확인 과정을 스마트 컨트랙트가 대체
- 새로운 수익 모델 : 가스비 대납 서비스, 가디언 수수료, 토큰화된 자산의 중개 수수료 등
- 글로벌 확장성 : 해외송금의 대체재
